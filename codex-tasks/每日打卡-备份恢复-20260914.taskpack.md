## 4. 任务范围

### 4.1 做什么（in-scope）
1. 设置区卡片（L579-583）新增两个按钮：`📥 备份` 和 `📦 恢复`（沿用 `btn btn-secondary` + `flex:1;padding:10px;font-size:13px` 样式）。
2. 新增「备份」函数：读取完整 appData（`loadData()` 或直接 `JSON.parse(localStorage.getItem(SK))`），生成 JSON 文件下载，文件名 `checkin-backup-<YYYYMMDD>.json`（如 `checkin-backup-20260914.json`）。下载实现：`Blob` + `URL.createObjectURL` + 临时 `<a download>`（推荐，纯前端无需依赖）。
3. 新增「恢复」流程：点击 📦 恢复 → 触发隐藏 `<input type="file" accept=".json,application/json">` → `FileReader` 读取 → 解析 JSON → **校验**（必须是合法 JSON，且对象含 `dataVersion` 字段且值为 5，或含 `tasks`/`habits`/`plans` 核心键之一；不满足则拒绝并提示）→ **自动备份当前数据**（把当前 `loadData()` 结果 push 进 `BACKUP_KEY` 数组，沿用 L895-898 的备份数组格式：`backups.push({...})`——先读 L892-900 了解现有备份记录字段结构并复用）→ 用户确认（`confirm('将从备份恢复全部数据，当前数据已自动备份，确定继续？')`）→ 恢复（写入 SK 键：`saveData(恢复后的对象)`，并强制 `恢复对象.dataVersion=5` 与 `lastBackup` 同步）→ `showToast('✅ 数据已恢复，请刷新页面')`。
4. 恢复成功后提示刷新；若确认前用户取消，则**不写入任何数据**。

## 5. 技术要求与约束

- 环境：Windows 11 / 浏览器（Chrome/Edge 均可）；代码为纯前端单文件 HTML，无构建步骤
- 编码：文件保持 **UTF-8 无 BOM**；行尾保持 **CRLF**（若用脚本/工具编辑，禁止整体转 LF；建议用 Node 脚本做精确字符串替换，替换后保持原换行）
- 风格：新函数用驼峰命名（如 `backupData()` / `restoreData()` / `handleRestoreFile()`），与现有代码一致；新增 HTML 用现有 class
- 安全：恢复时**必须**先自动备份当前数据到 `BACKUP_KEY`；恢复数据必须校验（拒绝非法 JSON / 缺核心字段 / dataVersion 不匹配）；文件名安全（日期拼接，无用户输入注入面）
- 兼容：不支持 FileReader 的老浏览器可降级为提示（`if(!window.FileReader){showToast('当前浏览器不支持');return;}`），不强制 polyfill
- 其他：下载文件名含中文没问题（建议文件名保持 `checkin-backup-` 英文前缀 + 日期）
